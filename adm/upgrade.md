# `oc adm upgrade`

> クラスタをアップグレードする、またはアップグレードチャネルを調整する

[`oc`](../oc.md) / [`oc adm`](../adm.md) / `upgrade`

## Usage

```
oc adm upgrade --to=VERSION [flags] [options]
```

アップグレードの状況を確認する、またはクラスタを新しいバージョンにアップグレードする

このコマンドはクラスタのアップグレードを支援します。引数を渡さない場合、現在のバージョン情報を取得し、アップグレードが進行中かどうか、アップグレードを妨げる可能性のあるエラーがないかを表示するとともに、そのクラスタで利用可能な推奨更新を示します。互換性のある更新の情報は、定期的に更新サーバーから取得されてクラスタにキャッシュされます。これらは、現在のバージョンからのアップグレードとしてサポートされていることが分かっている更新です。

--to=VERSION または --to-image=IMAGE を指定すると、利用可能な更新のいずれかへクラスタをアップグレードします。該当バージョンが存在しない場合はエラーを報告します。その後クラスタは自身をアップグレードし、その状況は "oc get clusterversion" および "oc describe clusterversion" で確認できます。

--to-multi-arch を指定すると、現在のバージョンのまま、シングルアーキテクチャのクラスタからマルチアーキテクチャのクラスタへアップグレードします。

利用可能なバージョンが無い場合や、cluster version operator のバグで更新情報を取得できない場合は、--to-image を、より強力で危険な --allow-explicit-upgrade と組み合わせられます。これにより、現在のバージョンからのアップグレードが推奨されているかどうかに関係なく、指定したリリースイメージの内容へアップグレードするようクラスタに指示します。1 つ前のパッチ (z ストリーム) バージョンへのロールバック (4.1.2 -> 4.1.1) は安全な場合もありますが、マイナーバージョンを 2 つ以上先へ進める (4.1 -> 4.3)、あるいはマイナーバージョンを 1 つ戻す (4.2 -> 4.1) と、データ破損やクラスタの完全な破壊を招く可能性が高くなります。

アップグレードのガードには、クライアント側とクラスタ側の 2 層があります。

クライアント側のガードには、クラスタが既にアップグレード中でないか、クラスタが障害を報告していないか、といったチェックが含まれます。通常はこれらの状態が解消されるのを待つか、解消に向けて対処するのが最善です。それでも、これらを承知の上で更新を実行すると決めた場合は --allow-upgrade-with-warnings を使用してください。

クラスタ側のガードには、リリースの検証とアップグレード可否の条件のチェックが含まれます。--force で押し切ることもでき、この値は ClusterVersion の spec.desiredUpdate.force に渡されますが、実行してよいのは次の場合だけです:

- 短期間のテストクラスタで、署名されていないリリースイメージをテストしている場合
- cluster-version operator の既知のバグを回避しようとしていて、指定したイメージの真正性を自分で確認済みの場合。
指定したイメージは、クラスタに対する完全な管理者権限で実行されます。出所が不明なイメージや、悪意がある可能性のあるイメージに --force を使用しないでください。

## Subcommands

- [`channel`](upgrade/channel.md) — 更新チャネルを設定またはクリアする
- [`recommend`](upgrade/recommend.md) — クラスタ更新の推奨情報を表示します。
- [`status`](upgrade/status.md) — 現在のクラスタバージョン更新、またはマルチアーキテクチャ移行の状況を表示する

## Examples

```bash
# 更新の状況と、利用可能なクラスタ更新を表示する
oc adm upgrade

# 最新バージョンに更新する
oc adm upgrade --to-latest=true
```

## Options

- `--allow-explicit-upgrade=false`
  アップグレード先が利用可能なバージョンの一覧に無くてもアップグレードします。

- `--allow-not-recommended=false`
  サポートはされているが更新推奨ではないバージョンへのアップグレードを許可します。

- `--allow-upgrade-with-warnings=false`
  アップグレードの進行中やクラスタの障害など、クライアント側のガードに引っかかってもアップグレードします。

- `--clear=false`
  アップグレードが要求済みでまだダウンロードされていない場合、その更新をキャンセルします。更新が開始した後では効果はありません。

- `--force=false`
  リリースの検証やアップグレード可否の条件など、クラスタ側のガードに引っかかってもアップグレードします。これを使ってよいのは、署名されていないリリースイメージをテストしている場合か、cluster-version operator の既知のバグを回避しようとしていて、指定したイメージの真正性を自分で確認済みの場合だけです。

- `--include-not-recommended=false`
  クラスタの構成上、推奨されない更新も追加で表示します。

- `--to=''`
  アップグレード先のバージョンを指定します。そのバージョンは、利用可能な更新の一覧に含まれている必要があります。

- `--to-image=''`
  アップグレード先のリリースイメージを指定します。

- `--to-latest=false`
  利用可能な最新（セマンティックバージョンが最大）のバージョンを使用します。

- `--to-multi-arch=false`
  現在のバージョンをマルチアーキテクチャにアップグレードします。

> 各コマンドの詳細については "oc adm upgrade `<command>` --help" を使用してください。

> すべてのコマンドに共通するグローバルオプションの一覧は "oc options" で確認できます。
